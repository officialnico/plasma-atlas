y, in Fourier space

From wiggles to sine waves to GENE's actual data

We'll go in three steps:

1. Look at what a "wiggle" along y looks like.
2. See how that wiggle is built out of sine waves.
3. See what GENE actually stores in its arrays.

01A wiggle along y

Imagine you're standing on the flux surface, walking along the binormal direction. As you walk, you measure the temperature fluctuation — how much hotter or colder it is than the average. You'd see something like this:

Temperature fluctuation as a function of y position

That's the real-space picture. At each y position, there's a number. In a simulation you'd store this as an array: T[0], T[1], T[2], ... — one value per gridpoint along y. If you have 256 gridpoints, that's 256 numbers.

02Same wiggle, built from sine waves

Now here's the magic of Fourier: any wiggle can be written as a sum of sine waves. Each sine wave has a wavelength (or equivalently, a wavenumber k_y) and an amplitude (how big it is). Add them all up and you get back your original wiggle.

Each slider controls the amplitude of one sine wave. The four faded curves at top are the individual sine waves. The bold curve at bottom is their sum — the actual wiggle.

So instead of storing the wiggle as 256 values of T(y), GENE can store it as 256 amplitudes — one for each k_y. Same information, different representation. One says "what's the temperature at each position?" The other says "how much of each sine wave is there?"

Why bother switching?

Because in y, the plasma is the same everywhere, each sine wave evolves on its own. The k_y=3 wave never affects the k_y=5 wave. So GENE can update each amplitude independently, in parallel, without doing any communication between them. That's the speedup.

03What GENE actually stores

Now let's connect this to the real GENE variables. GENE solves for a function called f — the distribution of plasma particles. f depends on position (x, y, z) and on velocity (v_parallel, mu). So at the most basic level, f is a 5-dimensional array.

But because of the y → Fourier swap, GENE doesn't store f(x, y, z, ...). It stores f̂(x, k_y, z, ...) — with k_y instead of y. Same information, different axis.

Animated · GENE's 5D data array — what each axis means
Real-space axes (gridded)
x · radial position · nx0 points
z · along field line · nz0 points
v_∥ · parallel velocity · nv0 points
μ · magnetic moment · nw0 points
Fourier axis (sine wave amplitudes)
k_y · binormal wavenumber · nky0 modes
For each k_y, GENE solves a separate problem. They don't talk to each other (at the linear level).

So when you see a GENE namelist with values like nx0=128, nky0=32, nz0=24, nv0=32, nw0=8 — that's the size of the array. Total memory: 128 × 32 × 24 × 32 × 8 ≈ 25 million complex numbers per species. That's the simulation.

And the kymin parameter you might have seen? That sets the longest wavelength sine wave — k_y values are kymin × 0, kymin × 1, kymin × 2, ... up to nky0 − 1. So kymin tells you the spacing between sine wave wavelengths, and nky0 tells you how many of them you keep.

Putting it together

GENE simulates plasma turbulence by storing the distribution function as a 5D array. The y axis is Fourier-transformed because the physics is symmetric there, so each k_y mode evolves independently. The other four axes (x, z, v_∥, μ) stay in real space because the physics depends on where you are. That's it. That's the whole architecture.
