§ 1 · CONTEXT

What is Kokkos, and why does anyone use it?

Kokkos is not a physics idea. It's a piece of infrastructure — a C++ library that lets you write one piece of code and have it run on whatever hardware is sitting in front of you: a normal CPU, an NVIDIA GPU, an AMD GPU, an Intel GPU. That's it. That's the whole pitch.

The reason this matters: supercomputers used to be made of CPUs that all looked alike, so you wrote code once for the CPU and you were done. Today's machines are heterogeneous — the top systems are essentially massive piles of GPUs, and different vendors ship different GPUs with different programming models (CUDA for NVIDIA, HIP for AMD, SYCL for Intel). If you want your simulation code to run on more than one machine, you either rewrite it three times, or you use a layer like Kokkos to write it once and let the library translate to whatever's underneath.

You write a parallel_for in C++ once. Kokkos compiles it down to whichever backend is available. The trade-off: you accept some abstraction overhead in exchange for not maintaining three separate codebases.

For our purposes, "gyselalib++ uses Kokkos" just means: it's written in performance-portable C++ aimed at running on the world's biggest machines. The new code's answer to the same problem is different — it uses Python with JAX, which plays the same role (write once, run on CPU or GPU) but trades some peak performance for much faster iteration. Same problem, different bet.

Spectral versus grid — two ways to store a function.

You have a function. You want a computer to hold it. There are two main strategies, and the choice between them is one of the biggest design decisions in any simulation code.

Strategy A — store values on a grid. Pick a bunch of points $x_0, x_1, \dots, x_{N-1}$, and store the value $f(x_i)$ at each one. Simple, intuitive, and what you'd do if you had to invent it from scratch. Derivatives become finite differences: $f'(x_i) \approx (f_{i+1} - f_{i-1}) / (2\Delta x)$.

Strategy B — store coefficients in a basis. Pick a set of "building-block" functions $\psi_0, \psi_1, \dots, \psi_{L-1}$, and write your function as a sum:

$$f(x) \;=\; \sum_{\ell=0}^{L-1} c_\ell \, \psi_\ell(x).$$
The numbers you store are the coefficients $c_\ell$, not values at points.

If the basis functions are well chosen, you can describe a smooth function with very few coefficients. This is called a spectral representation.

Why basis functions matter for plasmas

A magnetized plasma in equilibrium has particle velocities that are Maxwellian — a Gaussian bell curve in velocity space, $F_0(v) \propto e^{-v^2/2}$. Turbulence is a small wiggle on top of that big Gaussian. So most of the "shape" of the distribution function is already known; what's hard is the wiggle.

The clever choice for the velocity basis is the Hermite functions $\psi_\ell(v) = H_\ell(v) / \sqrt{2^\ell \ell!}$ — polynomials that are orthogonal with respect to the Gaussian weight. The first one, $\psi_0$, is just the constant $1$. So if your function is a pure Maxwellian, all of its information lives in a single coefficient, $c_0$. A grid would need hundreds of points to represent the same Gaussian. Move the demo's slider and watch.

CONNECTION TO THE NEW CODE the new code uses Hermite functions for the parallel-velocity axis and the related Laguerre polynomials for the magnetic-moment axis. The notebook you read showed a Maxwellian projecting onto exactly one coefficient — that's this picture, exactly. Gyselalib++ takes the other path: it stores the distribution function on a grid in velocity space.

The trade-off in one line

GRID

Store $f(x_i)$ at points.

  • simple, local, no special math
  • any function, no smoothness assumed
  • cost grows with feature density everywhere
  • derivatives are approximate

SPECTRAL

Store $c_\ell$ in a basis.

  • tiny for smooth functions near the background
  • moments (density, flow, temperature) are exact
  • derivatives can be exact for the right basis
  • basis must match the problem; conventions matter

Eulerian versus semi-Lagrangian.

Both methods solve the same equation: "take this blob and push it along with the flow." The difference is what you stand on while you do it.

The model problem is advection: a quantity $f(x, t)$ being carried by a velocity $u(x)$. The equation is

$$\frac{\partial f}{\partial t} + u(x)\,\frac{\partial f}{\partial x} \;=\; 0.$$
Read: "f is constant along trajectories that move at speed u."

There are two ways to discretize this — and the choice has nothing to do with what's right, only with where you choose to stand.

Eulerian: stand on the bank, watch the river

Put a grid down in space. At each grid point $x_i$, every time step, ask: "given the values of $f$ at me and my neighbours, what's $\partial f / \partial t$ here?" Then update $f_i$ accordingly. You never move; the field flows past you.

This is what most codes — including the new code — do. The right-hand side $-u\,\partial f/\partial x$ becomes a finite difference or a spectral derivative; the time step is some explicit scheme like Runge–Kutta 4.

Semi-Lagrangian: ride the river, sample at the bank

Same grid. But now the algorithm thinks: "the value of $f$ at grid point $x_i$ at time $t + \Delta t$ is equal to the value of $f$ at the point that just arrived at $x_i$." So trace the trajectory backwards from $x_i$ by one time step, find where it came from (call it $x_i^*$, which is generally not a grid point), and look up $f$ there by interpolating the old grid.

This is what GYSELA / gyselalib++ do. The whole equation collapses to "follow characteristics backwards and interpolate."

Top (Eulerian): the grid points sit still and exchange information with their neighbours each step. Watch the small arrows — they're stencils, not motion. So which is better?

Neither, in general. Eulerian methods are simpler to reason about and integrate cleanly with spectral methods (it's hard to "trace a characteristic" in Fourier space). Semi-Lagrangian methods can take much larger time steps without going unstable, because they don't have the usual "$\Delta t < \Delta x / u$" speed-limit — they follow the flow directly rather than letting it crash into a grid cell. The cost of that freedom is the interpolation, which can introduce its own dissipation if you're not careful.

CONNECTION TO THE NEW CODE the new code is Eulerian: it uses finite differences (radial, parallel) and spectral methods (binormal, velocity) on a fixed grid, with Runge–Kutta in time. Gyselalib++ is semi-Lagrangian: it traces characteristics on a fixed velocity-space grid. Both are valid; they just spread the difficulty differently.

Landau damping — a wave that fades without friction.

A wave in a plasma, with zero collisions and zero viscosity, can still die out. It does so by quietly handing its energy to a small population of particles whose speed matches the wave. This is Landau damping — one of the strangest and most checkable predictions in plasma physics.

The set-up

Imagine a one-dimensional plasma. The particles are described by a distribution function $f(x, v, t)$ — at every position $x$ and velocity $v$, $f$ tells you how many particles there are. The equilibrium $f_0(v)$ is a Maxwellian: a Gaussian centred on $v = 0$.

Now perturb the plasma a tiny bit, in a sine wave of wavelength $2\pi / k$. This creates an electric field oscillating at some frequency $\omega$, where for a "Langmuir" wave $\omega \approx \omega_p$, the plasma frequency. The wave has a phase velocity:

$$v_\phi \;=\; \frac{\omega}{k}.$$
The speed at which a crest of the wave moves.

The resonance

Most particles see the wave whoosh past faster than they themselves are moving — to them, it averages to nothing. But a few particles happen to be moving at almost exactly $v_\phi$. For those particles, the wave looks stationary: they sit in one of its electric-field troughs and get a sustained push.

Now here's the crucial bit, due to Landau (1946). On a Maxwellian, there are more particles slightly slower than $v_\phi$ than particles slightly faster, because the Maxwellian $f_0(v)$ is a decreasing function for $v > 0$ — its slope $\partial f_0 / \partial v$ is negative. The slower ones get accelerated by the wave (taking energy from it); the faster ones get decelerated (giving energy back). The slower ones win by a small margin. Net effect: the wave loses energy and decays. The damping rate is

$$\gamma_{L} \;\propto\; \left.\frac{\partial f_0}{\partial v}\right|_{v = v_\phi}.$$
The damping is set by the slope of the equilibrium at the resonant velocity.

No collisions, no viscosity, no entropy increase in $f$ — just clever bookkeeping in phase space. The wave's energy doesn't vanish; it gets sheared into ever-finer wrinkles in $(x, v)$ space until it's invisible at any practical resolution. This is called phase mixing.

FIG. 4.1 · PHASE SPACE AND THE WAVE IT EATS PRESS PLAY

Top: phase space — a heatmap of $f(x, v, t)$ with the Maxwellian background subtracted off. Watch how the perturbation gets sheared into thinner and thinner stripes. WHY IT'S A TRIPWIRE Landau damping has an analytically known rate that depends only on $k$ and on the shape of $f_0$. Every serious gyrokinetic code reproduces this rate as a benchmark. If your numerical scheme accidentally adds dissipation, the damping comes out too fast; if it loses energy in the wrong places, the rate is off. It's one of the cleanest "does this code do real physics?" tests there is. The new code's roadmap lists Landau damping as an M1 check.

ITG growth — turbulence eating a temperature gradient.

Landau damping makes a wave shrink. The ion temperature gradient instability does the opposite: it makes a wave grow, exponentially, because the plasma has more thermal energy in the middle than at the edge and the universe wants to even that out.

The free energy

A tokamak or stellarator plasma is hot in the core and cold near the wall. The temperature profile $T(r)$ falls off with minor radius. We measure how steep that fall-off is using a length scale:

$$\frac{1}{L_T} \;=\; -\frac{1}{T}\frac{dT}{dr}, \qquad \text{usually quoted as } R/L_T,$$
where $R$ is the device's major radius. Steeper gradient → larger $R/L_T$.

This gradient is what's called free energy: it's there to be released, and turbulence is the release mechanism. Below some threshold $(R/L_T)_{\text{crit}}$, the plasma is stable — small perturbations decay. Above the threshold, perturbations of certain wavelengths grow exponentially:

$$\delta T(t) \;=\; \delta T(0) \, e^{\gamma t},$$
where $\gamma > 0$ is the linear growth rate. Plot $\gamma$ as a function of perpendicular wavenumber $k_\perp \rho_s$ and you get a characteristic hump.

Here $\rho_s$ is the ion gyroradius — roughly the radius of the helical orbit an ion traces around a magnetic field line. Multiplying $k_\perp$ by $\rho_s$ gives the wavelength in units of "how big the ions themselves are". The hump in $\gamma(k_\perp \rho_s)$ typically peaks around $k_\perp \rho_s \sim 0.3$ to $0.7$.

FIG. 5.1 · THE ITG GROWTH-RATE CURVE MOVE THE GRADIENT

critical threshold $(R/L_T)_c$ 4.0

Top: the growth rate $\gamma$ versus normalized wavenumber. Below the critical gradient, the whole curve sits at or below zero — no instability. Above critical, a hump rises in the mid-$k_\perp \rho_s$ range. Bottom: a sketched time evolution at the most-unstable wavenumber — pure exponential growth in the linear phase. (In a real run, that growth saturates when nonlinear effects kick in — that's the turbulence.)

Why ITG matters for the whole confinement story

The ITG instability is the dominant cause of heat loss in tokamak and stellarator cores. When it goes unstable, eddies form at the scale of a few ion gyroradii and ferry heat outward across the magnetic surfaces, faster than collisions would. Every degree of confinement performance, every projection for ITER and W7-X, depends on getting this turbulence quantitatively right.

Predicting $\gamma(k_\perp \rho_s)$ in the linear regime is the gateway test. The shape of that hump and where it peaks are robust analytic results in simplified geometry. Any code that gets the hump shape and peak location wrong has a problem; any code that gets them right has earned a starting share of trust.

CONNECTION TO THE NEW CODE the new code's roadmap explicitly lists "linear ITG growth rates" as an M1 deliverable. The notebook you read built the bricks; M1 assembles them into the linear gyrokinetic operator and runs it through this test. If the growth-rate curve agrees with established codes on a standard geometry, that's a major credibility milestone.

Rosenbluth–Hinton — flows that refuse to die.

Turbulence wants to dissipate. But certain flow patterns in a tokamak shouldn't dissipate completely. There's a calculable, non-zero level they decay to and then sit at indefinitely. This residual is a beautiful and very specific prediction — and one of the cleanest things a gyrokinetic code can be asked to reproduce.

What is a zonal flow?

Inside a tokamak, picture the magnetic surfaces as nested tori — one inside the other like onion layers. A zonal flow is a flow that goes around these tori (poloidally), with a velocity that depends only on which "onion layer" you're on (the minor radius $r$). Crucially: a zonal flow has no variation in the toroidal direction, and so it doesn't experience the unstable physics that drives ITG. It just sits there.

More importantly, zonal flows shear the turbulent eddies that try to form on top of them, breaking them apart before they can grow. They're nature's brake on transport, and getting them right is essential to predicting confinement.

The Rosenbluth–Hinton calculation

Drop a small zonal-flow potential $\phi(r, t=0)$ into a plasma. Watch what happens. There's a fast oscillation called the geodesic acoustic mode (GAM), which damps over a few sound-transit times. After that damps away, you'd naively expect the flow to be gone — but it isn't. It settles to a residual level:

$$\frac{\phi(t \to \infty)}{\phi(0)} \;=\; \frac{1}{1 + 1.6\, q^2 / \sqrt{\epsilon}}.$$
Rosenbluth–Hinton (1998). Here $q$ is the safety factor and $\epsilon = r/R$ is the inverse aspect ratio.

The two parameters in the formula are properties of the tokamak's magnetic geometry. The safety factor $q$ measures how many times a field line wraps the long way around the torus per single trip the short way — it's typically between 1 and 5. The inverse aspect ratio $\epsilon$ is how "fat" the torus is — $\epsilon \approx 0.3$ for a typical tokamak. Plug in $q = 1.4, \epsilon = 0.3$ and you get a residual around $35\%$. That's the prediction: a third of the initial zonal flow survives forever.

WHY IT'S A TRIPWIRE The Rosenbluth–Hinton residual is one of the few exact analytic results in gyrokinetics that involves the full toroidal geometry. A code that gets it right has correctly implemented the magnetic geometry, the gyroaverage, and the field-solve all at once. A code that gets it wrong has something subtle broken — and it's usually impossible to figure out which without this test. The new code's roadmap, again, lists this as an M1 check.

§ 7 · REFERENCE

Recap, and a pocket glossary.

You can now read the comparison table that originally prompted these questions and know exactly what each row says.

KOKKOS

A C++ portability library. Write code once, run on any CPU or GPU. Used by gyselalib++. The new code uses JAX for the same purpose.

SPECTRAL VS GRID

Two ways to store a function. Spectral: as coefficients in a basis (tiny for smooth functions). Grid: as values at points (general but data-heavy). The new code is spectral in velocity and binormal; grid in radial and parallel.

EULERIAN

Stand at fixed grid points and watch the field evolve there. Pair with finite differences or spectral derivatives. The new code is Eulerian.

SEMI-LAGRANGIAN

Each step, trace characteristics backwards from each grid point and interpolate the old field. Pair with larger time steps. Gyselalib++ is semi-Lagrangian.

LANDAU DAMPING

A collisionless wave decays because particles at the wave's phase velocity exchange energy with it asymmetrically. Damping rate $\gamma_L$ is set by $\partial f_0 / \partial v$ at the resonant velocity. The canonical "is the code real?" test.

ITG GROWTH

Ion Temperature Gradient instability. Above a threshold gradient, perturbations grow exponentially with rate $\gamma(k_\perp\rho_s)$, a hump peaking near $k_\perp\rho_s \sim 0.5$. Drives most core heat loss.

ROSENBLUTH–HINTON RESIDUAL

A zonal flow in a tokamak doesn't decay to zero — it decays to $1/(1 + 1.6\, q^2/\sqrt{\epsilon})$. Tests geometry, gyroaverage, and field-solve all at once.

WHY ALL THESE TESTS

Gyrokinetic bugs are silent. None of these checks "crash" if the physics is wrong — they just give the wrong number. Cross-checking against analytic results is the only way to know.

If the M0 notebook's order-of-accuracy plots had slopes of $-1$ instead of $-4$, you'd know something was wrong in the bricks. If a future M1 notebook runs Landau damping and the rate doesn't match the analytic value, you'd know something is wrong in the assembly. That's the whole point of the discipline: every stage of construction has its own external checks, and you don't move on until they pass.
