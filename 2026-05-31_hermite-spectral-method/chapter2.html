Chapter 2 · the actual optimization

The thing
Hermite beats.

Last chapter: a curve is a few meaningful numbers. You felt it with the knobs.

Now the real question — beats what, exactly? What's the dumb, obvious alternative, and why is the knob-trick worth it? And the part you spotted yourself: why was anyone unsure it'd work?

Step 1 — meet the dumb way

Just measure the height everywhere.

The obvious way to store a curve needs zero cleverness: pick a bunch of speeds, write down how tall the curve is at each one, connect the dots. That's a grid. It's what the big established codes do.

It always works. Any shape, no thinking required. But it's expensive — you're carrying a number for every single sample point. Here's the same bell curve stored both ways, with a live count of how many numbers each method needs:

A clean bell needs 1 knob vs 50 grid points — same curve, 50× less.

Right now the curve is a perfect bell, so the knob side nails it with almost nothing while the grid lugs around 50 numbers for the same picture. That gap, multiplied across a million points in space, is the whole speed story.

✓

When the curve is simple, the knobs crush the grid — far fewer numbers, identical result. The grid pays full price for detail that isn't there.

Step 2 — the catch you already guessed

But what if the curve gets ugly?

The sharp question: if it's such a free win, why was it ever in doubt? Here's the answer, and now you can do it with your hands.

See what happens? The grid doesn't flinch — 50 numbers, fits perfectly, no matter how ugly you make it. It never cared what shape the curve was. But the knobs start to struggle: to chase the new bumps and ripples you have to keep spending more and more knobs, and if you don't, the blue curve peels away from the target.

!

This is the catch: the knob-trick's advantage is conditional. Cheap and brilliant when the curve is a clean bell — but as the curve gets wild, the knobs you need pile up and the advantage shrinks. The dumb grid is bulletproof; the clever knobs are only clever when the curve cooperates.

Step 3 — so that's the whole bet

Now the paper makes sense.

Everything in that document hangs on one wager: in a real fusion plasma, does the curve stay close enough to a clean bell that the knobs keep winning?

For decades people assumed no — that in the violent, turbulent regions that matter most, the curve goes ugly exactly where the knobs fail. So everyone used the bulletproof grid. Then someone finally tested the knobs in one of those violent regions (a tokamak edge) and found: the curve was messier than a bell, but not so messy that the knobs broke. A modest number kept up. The old fear was overblown.

✓

That test is why the new code is even proposable. But it was a tokamak. The new code bets the same holds in a stellarator — a more twisted machine that might warp the curve in new ways nobody's measured. That single unanswered question — do the knobs keep up in a stellarator? — is the entire risk the paper keeps circling.

What you now understand.

✓ The alternative to Hermite is a grid — store the curve's height at many sample points. Dumb, bulletproof, expensive.

✓ Hermite stores a few meaningful knobs instead. Cheap and brilliant — when the curve is bell-like.

✓ The win is conditional: ugly curve → knobs pile up → advantage shrinks.

✓ The paper's whole bet: plasma curves stay bell-enough that knobs win — proven in tokamaks, unproven in stellarators.
